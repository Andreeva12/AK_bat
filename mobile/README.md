# AKBata Mobile — автотесты (Appium)

Автоматизированное тестирование Android-приложения **AKBata** (доставка воды,
Flutter, пакет `com.shvaiberovsa.akbata`) через Appium.

Основной стек — **WebdriverIO + Mocha + Chai** (JavaScript), Page Object
Model. В `test/specs/` рядом лежит также независимый набор тестов на
**Python + pytest + Appium-Python-Client**, написанный через Appium
Inspector — оставлен как альтернативный референс, оба стека не запускаются
одновременно.

## Требования

- Node.js 18+, установленные зависимости: `npm install`
- Android SDK (`ANDROID_HOME`/`ANDROID_SDK_ROOT`), запущенный эмулятор или
  подключённое устройство (`adb devices`)
- Appium 3.x с драйвером `uiautomator2`, установленный **глобально**
  (`npm install -g appium && appium driver install uiautomator2`) — проект не
  тянет Appium как локальную зависимость
- Установленный на устройстве APK приложения (тесты не переустанавливают
  его — см. `appium:noReset` в `wdio.conf.js`)

## Запуск

```bash
# Появится тестовый аккаунт: телефон и пароль задаются в переменных окружения
# (или заданный через .env — см. переменные ниже)

# Appium должен быть запущен отдельно ЛИБО поднимется автоматически
# сервисом @wdio/appium-service (см. services в wdio.conf.js)

npx wdio run wdio.conf.js --spec ./test/specs/login.spec.js
```

**Важно:** запускайте ровно один `--spec` файл за раз. Передача нескольких
`--spec` флагов в одной команде обходит настройку `specs` в `wdio.conf.js`
(вложенный массив, форсирующий последовательный запуск в одном воркере) и
поднимает несколько параллельных воркеров, которые бьются за один и тот же
физический эмулятор — сессии Appium начинают падать случайным образом.
Это не баг тестов, а особенность окружения (единственный эмулятор).

Полный прогон всех спеков одной командой (`npx wdio run wdio.conf.js`, без
`--spec`) технически возможен благодаря вложенному массиву в конфиге, но пока
**не гарантирует чистое состояние между файлами** — см. раздел «Известные
ограничения» ниже.

### Переменные окружения (`.env`, необязательно)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ANDROID_DEVICE` | `emulator-5554` | serial устройства/эмулятора для adb и capabilities |
| `TEST_PHONE_LOCAL` | _(задайте)_ | номер тестового аккаунта (без `+996`) |
| `TEST_PASSWORD` | _(задайте)_ | пароль тестового аккаунта |

## Структура проекта

```
pages/          — Page Object Model, один класс на экран/компонент
test/specs/     — тест-файлы (*.spec.js — WebdriverIO, test_*.py — pytest)
utils/          — общие хелперы (ввод текста, запуск приложения, системные диалоги)
wdio.conf.js    — конфигурация WebdriverIO/Appium
```

Ключевые утилиты:
- `utils/appLaunch.js` — `ensureOnHomeScreen()` (доведение до главного экрана
  после холодного старта: онбординг → выбор роли → главный экран) и
  `returnToHomeScreen()` (возврат на главный экран между тестами нажатиями
  "Назад", с резервным перезапуском activity через adb, если "Назад" не
  срабатывает)
- `utils/adbInput.js` — ввод текста через `adb shell input text`/IME,
  обход debug-оверлея, перекрывающего нижнюю часть экрана
