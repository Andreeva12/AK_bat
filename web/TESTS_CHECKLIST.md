# Чек-лист автотестов — админ-панель Ак-Бата

Этот файл — карта того, что уже покрыто автотестами, чтобы новый человек в команде
за 5 минут понял: что проверено, где лежит, и с чего начать, если нужно что-то
добавить или разобраться в падении.

Всего: **142 теста в 19 файлах** (по `npx playwright test --list`). Каждый `.spec.js` файл — это набор сценариев для
одной страницы/фичи админки; внутри него несколько `test(...)`.

Как читать: `[x]` — тест написан и покрывает сценарий. Колонка **Page Object** —
файл в `pages/`, который тест использует (там лежат селекторы и методы действий).
Колонка **Заметки** — флаки/нюансы, о которых полезно знать, прежде чем чинить
падение (см. также [README.md](./README.md#известные-нюансы-сайта)).

Пометка **(дефект)** в названии теста — тест фиксирует *текущее* (ошибочное) поведение
продукта и упадёт, когда дефект исправят: тогда его нужно переписать на правильное поведение.
Тесты, меняющие данные (создание категории/пользователя/товара/покупателя), сами удаляют
за собой созданное в `finally`.

## Известные дефекты продукта, найденные тестами

1. Фильтр статуса на `/orders` не фильтрует таблицу.
2. Поиск пользователей по email всегда возвращает пустой список, даже для существующего email.
3. Поле "Пароль" в форме пользователя не помечено `*`, но обязательно (422).
4. Способ доставки/оплаты/статус оплаты в форме заказа выглядят выбранными, но значение пустое.
5. Тексты валидации зависят от способа получения сессии: после входа через UI — русские, при
   восстановленной сессии — английские ("The field is required."). В тестах используется
   `REQUIRED_FIELD_TEXT` из `utils/auth.js`.
6. Нестабильность песочницы: API `https://ak-bata.i7.kg/api` периодически перестаёт отвечать
   (таймауты), из-за чего падают все тесты сразу.
7. Поиск (параметр `where=title(like)%значение%`) не фильтрует результаты на бэкенде —
